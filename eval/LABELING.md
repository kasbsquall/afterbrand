# Labeling guide

You label sentences from a company blog. On Sept 10, 2026 the company renamed two products: **Fusion is now Builder Code** and **Publish is now Builder Content** (source: https://www.builder.io/blog/builder-product-name-change). Each item is one sentence that contains the word Fusion or Publish (any case), with the page title, the page's publish date and the paragraph around it.

Your label answers one question: **if the content team updated this page today, should this sentence use the new name?**

## Labels

**change**: the sentence uses the old name for the product as it exists today, so a reader now would see a retired name. A how-to, a feature description or a comparison that describes how the product works now is change, even in an older post.

**keep**: the old name is right where it is.
- Historical: the sentence describes something that happened before Sept 10, 2026 (a launch, an announcement, a past event, a past release).
- Dated changelogs and release notes: they record what shipped under the name of the time.
- Not prose: URLs, slugs, file names, code identifiers, command names, quoted UI labels.
- Contracts, invoices and pricing records: the source says references to the old name stay valid.
- Common word: the word is not the product ("the fusion of design and code", "click publish", "publish your page", "publishing workflow", "the publish button").
- Another company's product that uses the same word.

**unsure**: you cannot tell from the sentence and its context, for example a heading with no verb, a sentence that could be read as historical or current, or a capitalized "Publish" that may be the verb. Use it only when a careful editor would have to ask.

## The rule's exceptions, as the team wrote them

Fusion: "Keep the old name where it is historical (describes something that happened before the rename), in dated changelogs or release notes, in URLs, slugs, code and quoted UI strings, and in contract, pricing or invoice language: the source says anything referencing the old name is still valid. Keep the common word fusion when it does not name the product."

Publish: "Only the product name changes. Keep the verb and noun publish or publishing (publish a page, the publish button, publishing workflow) unless it clearly names the Builder product. Same historical, changelog, URL, code and contract exceptions as Fusion."

## How to work

- Judge each item alone, from its own sentence, context, title and date.
- A sentence that mixes history and present ("Since we launched Fusion in 2024, it has become the way teams ship") is change: the present clause names the current product.
- Give one short note per item (under 15 words) saying why, in your own words. Do not copy the sentence.
- These labels are ours, made for this evaluation. They are not Builder's.
